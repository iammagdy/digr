SAMPLE EVERY NAMED SOURCE at least once, and PREFER THE SOURCE'S OWN LISTING to a keyword search: when the catalog has an endpoint that takes the channel, page or account itself (a channel's videos, an account's posts: catalog_search finds it by its capability, for example `youtube.channel.videos`, `x.user.posts`, `tiktok.user.videos`; when it needs an id, look the id up with the catalog's own lookup endpoint) take one sample per named source from it, with the handle or id that returned items, give the `account` filter `calls` (for each value, in the same order, the id of the saved call that read THAT source), and keep the topic's items with the relevance rule; a keyword search that names the source in its search text is the fallback, in the language the source writes. A plan that searches the whole platform by keyword for sources no sample shows is refused while such an endpoint exists and none was sampled. The engine then reads each named source in turn, each up to its share («٥ من كل قناة»): a named source that no sample shows is told to the customer on the card before they approve. When you carry such a plan out, search each named source separately: finish is refused while a named source has no saved item. The topic is judged on the topic only, in the item's own language: an English video of a named English channel about an Arabic topic is on-topic.
- KEEP THE TIME OF A TIMESTAMP. When the source gives a date AND a time (an ISO text, seconds or milliseconds since 1970, a long English form), map the full moment: `new Date(r.createdUtc * 1000).toISOString()`, never `.slice(0,10)`, `.split('T')[0]` or `.substring(0,10)`; the file shows it in Cairo time, and a date alone only when the source gives no time. Code removes such a cut from your mapping when it can prove nothing else changes.
- A PERIOD IS READ IN WINDOWS BY CODE: when the customer asks for a period («آخر ٣ شهور») give the `period` filter and map the date; a source that ends before the target (a search stops after about two thousand results) is asked again by code with the end of the window moved back, using its own since/until or start/end inputs.
- THE SAME JOB, CHEAPER: when you skip a cheaper source on purpose, skip EVERY cheaper source of the same job by name (`skip`), or sample it; one sentence (`why`) does not excuse several. A cheaper source that answered empty for ONE input (one post, one page) is asked once more with another item before a dearer one is chosen: one empty answer is not a verdict on a source.
- A SOURCE THAT GIVES ONLY A RELATIVE TIME («قبل ٣ أيام», «4 days ago», «2 weeks ago»): map the value as the source gives it. Code turns it into an approximate date from the moment of the read, accepts an item for the period when it may fall inside it, and the file and the card say the dates are approximate; never invent a date yourself, and never end a plan because the date is relative. `catalog_search` shows `dates: "relative"` or `"absolute"` for a source whose own date fields say so: when the request has a period and a source of the same job costs about the same with `dates: "absolute"`, prefer it (its dates are exact); a plan on a source with relative dates is valid.
