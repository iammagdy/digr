# انحراف نسخ الـ migrations بين الريبو والإنتاج (DT-20261119-02، قرار D-0105)

رابط الطلب: سيُضاف بعد فتح الـ PR

## المشكلة
- فحص Supabase Preview فشل برسالة «Remote migration versions not found in local». Megz صدّر جدول `supabase_migrations.schema_migrations` من الإنتاج (٢٨ صف، قراءة فقط، `tests/fixtures/prod-migration-versions-2026-11-19.txt`) والمقارنة مع ٤٢ ملف في الريبو أعطت:
  - **أ) ٨ migrations بنفس الاسم ونسخة مختلفة**: النسخة المسجّلة في الإنتاج غير نسخة ملف الريبو (الإنتاج اتطبّق بـ MCP فاتسجّل بتوقيته). دول اللي بيطلّعوا الخطأ.
  - **ب) ١٤ ملف في الريبو مش مسجّلين في الإنتاج**: أغلبهم اتطبّق باليد في SQL editor (المحرر مبيسجّلش)، وlazem يتثبّت إنه فعلًا موجود قبل أي تسجيل.

## القاعدة
مفيش `supabase db push` ولا `migration repair` من الفريق، ومفيش أي تغيير في schema الإنتاج. أي حاجة تتثبّت إنها ناقصة بترجع لـ CTO كقرار منفصل.

## الحل (٣ خطوات، بالترتيب)
1. **تحقق للقراءة فقط** (`01_verify_readonly.sql`): استعلام SELECT واحد، بيطلّع صف لكل migration من الـ ٢٢ (٨ + ١٤): هل كائناتها موجودة في الإنتاج (جداول، أعمدة، فهارس، constraints، RLS، صلاحيات، triggers، دوال بتوقيعها وصلاحياتها، extensions، صفوف registry)؟ الحالة `present` / `PARTIAL` / `MISSING`، وعمود إضافي للمعلومة بس: هل جسم الدالة لسه فيه السطر المميّز بتاع تعريف الريبو (ممكن يكون اتبدّل عمدًا بـ migration أحدث، زي سقف ٢٥٠٠٠ نقطة).
2. **الإصلاح في الريبو** (بعد ما الـ ٨ في المجموعة أ يطلعوا `present`): إعادة تسمية الـ ٨ ملفات لنسخ الإنتاج (محتوى الملف زي ما هو، `git mv` فقط، 100% rename) + تحديث أسماء الملفات في ٦ اختبارات بتقرأهم (الأسماء فقط، لا assertion اتغيّر ولا اتخفّف) + اختبار جديد `tests/migration-versions-match-production.test.ts`.
3. **تسجيل** (`02_record_proven_only.sql`، Megz بيشغّله): بيدخّل صف في `supabase_migrations.schema_migrations` **بس** لمجموعة ب اللي كل فحوصاتها الهيكلية صح وقت التشغيل (نفس فحوصات الاستعلام الأول، جوه الجملة نفسها). مبيشغّلش migration ولا بيغيّر schema ولا بيانات. يتشغّل مرتين من غير ضرر.

## ما تم التحقق منه
- على PostgreSQL محلي (replica بتقليد صلاحيات Supabase) طُبّقت الـ ٤٢ ملف: الاستعلام الأول طلّع `present` للـ ٢٢ (ما عدا migration الترحيب لأن `pg_net` مش موجود في replica)، وعلى replica فيها الـ ٢٨ بس طلّع المجموعة ب `MISSING`/`PARTIAL`. ٦ تخريبات (صلاحية لـ anon، trigger محذوف، RLS مقفول، حذف مسموح، فهرس محذوف، عمود محذوف) كلها اتمسكت. الاستعلام اشتغل جوه `BEGIN READ ONLY`.
- التسجيل: ١٣ صف دخلوا على replica الكاملة، ٠ على التانية، ٠ في التشغيل التاني.
- أجسام الدوال المحفوظة من الإنتاج يوم ٢٠٢٦-١٠-٢١ (`tests/replica/prod-definitions`) فيها السطور المميّزة للـ ٨ (دليل تاريخي للمجموعة أ).

## ما لم يتم التحقق منه
- حال الإنتاج الفعلي اليوم: ده اللي الاستعلام الأول مصمّم يثبّته.
- لو الـ Preview بيعيد تشغيل الـ migrations على قاعدة فاضية: `one_open_addon_per_file` بيرفض لو `missions` مش موجود (قيد قديم، مش من التغيير ده).
- Vault: `welcome_email_on_confirm` بيعتمد على سرّ `send-email-service-role-key` (مش بيتفحص: سرّ).

## متابعات
- لو أي migration طلع `PARTIAL`/`MISSING`: قرار منفصل من CTO (مفيش تطبيق من الفريق).
