## 1. Scope & Implementation Overview

Per COMMANDER design review (`3882c597-fc04-435a-a26e-c3249a8fa578`), «unknown stays null» means the system does not assume anything either way for endpoints with null or unknown pagination style. Endpoints with unknown style continue today's behavior where `has_more` and `next_cursor` derive from the live response, without prematurely cutting them to a single page. Single-page stop with the honest Arabic stop reason applies **strictly and only** when the contract explicitly specifies `style: "none"`.

### 1. Gateway Contract Use & Stop Reason (`agent/src/gateway.ts`)
- **Contract Pagination Ingestion:**
  - Extended `loadContractsRegistry()` and `getContractPagination(endpoint)` to extract `style` (`"cursor" | "page" | "offset" | "none" | null`) in addition to `max_page_size` and `page_size_param`.
  - Added cache management helper `clearCachedContracts()`.
- **Honest Arabic Stop Reason Enforcement (DIGER-TRUTH §6):**
  - Exported `CONTRACT_SINGLE_PAGE_STOP_REASON = "المصدر لا يدعم صفحات أكثر"` and helper `contractStopReasonOf(endpoint)`.
  - `contractStopReasonOf(endpoint)` returns `"المصدر لا يدعم صفحات أكثر"` **only** when `pagination?.style === "none"`. When style is unknown/null or unstated, it returns `null` (zero assumptions).
  - In `tregCall`, when an endpoint's contract explicitly declares `style: "none"`:
    - `has_more: false`
    - `next_cursor: null`
    - `stop_reason: "المصدر لا يدعم صفحات أكثر"`
  - When style is unknown/null or no contract is present:
    - Today's behavior exactly: `has_more: reading?.hasMore ?? null`, `next_cursor: reading?.nextCursor ?? null`, and no `stop_reason` is added.
  - For endpoints with declared pagination styles (e.g. `cursor`, `page`, `offset`), existing cursor and `has_more` indicators are preserved unchanged.
- **NEVER-TOUCH Compliance:**
  - Preserved all ledger hold, quote, and pricing logic untouched.

### 2. Universal Circuit Breaker Interplay (`src/lib/treg/circuitBreaker.ts`)
- **Contract Drift & Unknown Status Invariant (Point 5.4 / D-0198):**
  - Added explicit documentation and validation via `isAvailableForContract(endpointId, contract)`.
  - Contract synthesis status (`"unknown"`, `"partial"`) or schema drift (`drifted: true`) **never** blocks an endpoint by itself.
  - All 3,276 endpoints start with circuits in `closed` state at boot.
  - Only real runtime failures observed in the process (3 consecutive 400s or 5xx, or a failed control probe) trip the circuit to `open`.
