## What This Does for the Customer

When customers run data research missions or automated intelligence collection across TREG (The Research Endpoint Gateway), upstream external providers periodically experience transient outages, rate limits, or broken schemas. Previously, repeated calls to failing endpoints resulted in high mission latency, redundant failures, wasted customer retries, and corrupted responses.

Phase 2 introduces automated runtime reliability and circuit breaking:

1. **Dead Endpoints Skipped for a Short Cooldown:**
   - When an endpoint encounters repeated failures (3 consecutive 400 or 5xx errors), its circuit breaker trips to `open`.
   - The planner's candidate generation (`catalogView.ts`) and dispatcher (`asyncTreg.ts`) immediately bypass open endpoints, protecting customer missions from wasting time on dead providers and automatically routing to healthy alternatives.
   - A 5-minute cooldown allows transiently failing endpoints to recover into `half-open`, testing single recovery calls before restoring full traffic.

2. **`Retry-After` Header Honored on 429:**
   - Upstream rate limits returning HTTP 429 are parsed for `Retry-After` headers (supporting both integer seconds and RFC HTTP dates).
   - If the requested delay is reasonable ($\le 10$ seconds), the client automatically pauses and retries instead of immediately aborting customer jobs.

3. **Safe Retries with Idempotency:**
   - Transient upstream errors (HTTP 502 Bad Gateway, 503 Service Unavailable, 504 Gateway Timeout, and network timeouts) are retried with bounded exponential backoff (up to 2 retries).
   - All retries attach `X-Treg-Idempotency-Key` headers to ensure external providers never double-charge or execute duplicate actions.

4. **Diagnosis on HTTP 400 (Control Request Probe):**
   - HTTP 400 Bad Request can represent either client input syntax issues or upstream provider schema/outage failures.
   - On a 400 response, the client executes a minimal documented control probe request before allowing any parameter rewrite.
   - If the minimal control probe also fails with 400, the failure is diagnosed as a provider-side outage, tripping the circuit breaker immediately with an extended 30-minute cooldown and preventing fruitless query rewriting.

5. **Detection of HTTP 200 Provider Business Errors:**
   - Providers that respond with HTTP 200 containing error bodies (e.g. `{ "error": "...", "code": 400 }`) are detected and treated as true failures, properly feeding into the circuit breaker and telemetry.

6. **Clean, Data-Driven Registry (D-0086 Compliant):**
   - Initial endpoint health statuses are populated strictly from in-repo contract data (`data/treg/treg_research_endpoint_registry.json`) and live telemetry.
   - Zero provider names or hardcoded endpoint IDs in source code. If contract data is absent, the system safely defaults to closed/available without errors.

## Technical Deliverables

### 1. `src/lib/treg/circuitBreaker.ts`
- Implements `EndpointCircuitBreaker` with states `closed`, `open`, and `half-open`.
- Cooldown thresholds: 5 minutes default (`DEFAULT_COOLDOWN_MS`), 30 minutes for control probe failures (`EXTENDED_COOLDOWN_MS`).
- State transitions: 3 consecutive failures trip `closed` $\to$ `open`; cooldown expires $\to$ `half-open`; single success in `half-open` $\to$ `closed`; single failure in `half-open` $\to$ `open`.
- In-repo registry loader `loadResearchRegistry()` and fixture injectors `setResearchRegistry()` / `clearResearchRegistryCache()`.

### 2. `agent/src/llmPlanner/catalogView.ts`
- In `candidatesFor()` and `tregCandidatesFor()`, checks `circuitBreaker.isAvailable(endpointId)` and excludes open-circuit endpoints from model candidate views.

### 3. `src/functions/shared/tregClient.ts`
- `parseRetryAfter()`: Handles integer seconds and HTTP dates.
- Transient retry loop: Backoff on 502/503/504/timeout up to 2 retries with `X-Treg-Idempotency-Key`.
- HTTP 200 payload error detection: Inspects parsed response bodies for `code >= 400` or error strings.
- Control probe execution: `executeControlProbe()` evaluates minimal documented requests on 400.

### 4. `agent/src/asyncTreg.ts`
- Early rejection: Prior to dispatching jobs, checks `circuitBreaker.isAvailable(endpointId)`. If open, immediately rejects with `{ ok: false, blocked: "circuit_open", error: "Endpoint circuit is open due to recent repeated failures" }` without calling `callFn`.
- Telemetry recording: Records success and failure back to circuit breaker.

### 5. `tests/circuit-breaker-reliability.test.ts`
- 16 test cases covering all requirements:
  - Boot initialization and registry fallback.
  - State transitions, cooldown timing, half-open recovery, and manual reset.
  - Candidate generation bypass.
  - `Retry-After` header parsing and retry execution.
  - Idempotency headers on transient gateway failures.
  - HTTP 200 provider error detection.
  - Control probe diagnosis on 400.
  - Early rejection in `asyncTreg.ts`.
