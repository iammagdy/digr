### 1. Point 3.1: Universal Retrieval Contract & Pagination State Machine
- **File:** `agent/src/llmPlanner/retrievalContract.ts` (NEW)
- **Core Interfaces & Functions:**
  - `EntityScope`: `"authored_by" | "about"`
  - `StopReason`: `"terminal_cursor" | "target_reached" | "window_crossed" | "budget_reached" | "repeated_cursor" | "repeated_page"`
  - `FrozenTimeWindow`: `{ startUtc: string; endUtc: string; customerTz: string }`
  - `PaginationState`: Complete state keeping endpointId, provider, queryHash, window, cursor, seenCanonicalIds, acceptedCount, pagesFetched, stopReason.
  - `freezeTimeWindow(months, customerTz, referenceDate)`: Freezes time window deterministically.
  - `isRowDateInWindow(rowDate, window)`: Checks date bounds inclusively.
  - `shouldStopChronologicalScan(rowDates, window, minConsecutivePastWindow)`: Enforces chronological scan boundary. **Pinned Post Invariant:** A single old post at index 0 does NOT prematurely terminate traversal; requires at least `minConsecutivePastWindow` (default 2) consecutive older posts or non-pinned post past cutoff to stop.
  - `initPaginationState(options)` & `stepPagination(options)`: State machine managing discrete paging transitions, canonical ID deduplication, repeated cursor detection, and clean termination.
  - `buildHonestShortfallQuestion(options)`: Generates honest Arabic question (`«جرّبنا البحث في N تغريدة من [الحساب] على [المنصة] بالشروط التي كتبتها ولم نجد نتائج متطابقة. تحب نسلّمك الموجود، ولا نوسّع البحث؟»`).
  - `canAskShortfallQuestion(options)`: Forbids emitting shortfall question before budgeted pages are read when the account has more posts and call budget remains.

### 2. Point 3.4: Runtime Page-Size Clamping
- **Files Modified:**
  - `agent/src/gateway.ts`: Added generic `clampOutgoingPageSize(endpoint, params)` and wired it into `tregCall` and `tregCallBoundOf`.
  - `agent/src/tools.ts`: Imported `clampOutgoingPageSize` and applied it in `treg_call` and `collect_pages`.
- **Invariants:**
  - STRICT Zero-Guessing: Outgoing parameters are clamped ONLY when the endpoint's contract explicitly defines BOTH `page_size_param` AND `max_page_size`.
  - If contract has no `page_size_param` or `max_page_size` is null, parameters remain completely unchanged (arbitrary fields like `count` or `num` are never guessed).
  - Generic: Zero hardcoded endpoint IDs, provider brand names, or parameter fallback lists.
